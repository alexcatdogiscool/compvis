\subsection{System Overview}

The timestamp of an input image is used to calculate the subsolar-point (SP), the location on the globe where the sun is directly overhead for that time.
A Convolutional Neural Network (CNN) is used to estimate the solar elevation of an image. Using the solar elevation of the sun in the scene,
and the SP for the given image, a circle of possible locations can be derived for where the image must have been taken.
Multiple candidate circles can be derived when given multiple images from the same location at different times of year.
The intersection of these candidate sets can be taken to arrive at 2 unique points on the globe where the image must be taken from, mirrored acros the equator.

% ---- 3B: CNN Architecture & Transfer Learning ----
\subsection{CNN Architecture and Transfer Learning}

The image classifier model, EfficientNet [cite], was used as a backbone architecture for determining solar elevation
from images. A pre-trained version of this CNN for the purpose of image classification using the ImageNet-1K dataset was used,
as important feature recognition methods such as edge detection and shadow detection are backed into the pre-trained weights. These fetures are
important when determining solar elevation.

The origional classifier head was replaced with a feature head of 32 bins.

The backbone network $f_\phi$ maps an input image $\mathbf{I} \in \mathbb{R}^{H \times W \times 3}$
to one of 32 bins, each representing $\frac{90}{32}=2.81$ degrees for solar elevation:
\begin{equation}
    \hat{\beta} = f_\phi(\mathbf{I}), \quad \hat{\beta} \in [0,\, 32].
    \label{eq:cnn}
\end{equation}

\todo{Explain the training objective, e.g.\
$\mathcal{L} = \frac{1}{N}\sum_{i=1}^{N}(\hat{\theta}_i - \theta_i)^2$.}

During training, Loss is calculated using KL Divergence, which measures how different two probability distributions are.
The Loss function can be defined as:
\begin{equation}
    Loss = \Sigma(P(target) * log(\frac{P(target)}{Q(predicted)}))
\end{equation}

During inference, predicted solar elevation can be extracted from the bins by taking the expected value of the distribution as follows:
\begin{equation}
    \hat{\theta} = \Sigma(softmax(logits)[i] * binCenter[i]).
\end{equation}

This enables the model to be able to predict a smooth output for elevation rather than 32 discreat bins.

A dataset consisting of 6467 equirectangular panorama images taken from the Google street view API was manually labels for solar elevation.
The labelling split the set into two categories:
\begin{itemize}
    \item No Visible Sun
    \item Visible sun + manually labeled elevation
\end{itemize}
This resulted in 2404 clean images with ground truth labels.

Each panorama was used to create 12 training images with the following randomized parameters:
\begin{itemize}
    \item Feild of View. $FOV \in [50,\, 90]$.
    \item Yaw $\in [0,\, 360]$ degrees.
    \item Pitch $\in [-30,\, 30]$ degrees from horizon line.
\end{itemize}
The final training set consisted of 28,848 images labeled with solar elevation.

1,000 of these images were kept out of traing and used for evaluation resulting in a total training
set size of 27,848 images.

The ground truth for the training set is converted from degrees to a gausian with sigma=2.5 centered at the closest bin.
This results in a soft label for each image where the probability mass is spread across roughly $\pm5$ degrees of the true elevation.

% ---- 3D: Sun-Earth Geometric Model ----
\subsection{Sun--Earth Geometric Model}

\todo{Explain the astronomical model you use to compute solar elevation $\theta$
given observer latitude $\phi$, longitude $\lambda$, date, and UTC time $t$:
\begin{equation}
    \theta = g(\phi, \lambda, t),
    \label{eq:sunmodel}
\end{equation}
where $g(\cdot)$ is the Solar Position Algorithm (or equivalent). Cite the
algorithm. Note the precision achievable ($<0.01°$ for SPA).}

The elevation of the sun, paired with an accurate timestamp of when such elevation is measured provides a narrow search range for the location
of where such an elevation was measured.

The subsolar point can be easilly calculated for a given timestamp. The declination of the sun $\delta$ can be aproximated by:
\begin{equation}
    \delta = -4092797cos(\frac{2\pi}{365}(M+10)).
\end{equation}
Where M denotes the day of the year. The constant 0.4092797 represents the maximum declination angle of the sun in radians, namely,
23.45 degrees.

Next, for a time $\tau$ in hours rooted at UTC+0, longitude of the sun is calculated as:
\begin{equation}
    \lambda = \frac{360\tau}{24}
\end{equation}

Next, observe that for a given measured sun elevation $e$, and sun SP $(\delta, \lambda)$, the only points on the globe whos sun elevation is measured
as $e$ form a circle around the SP. this circle represents all possible locations in which such an elevation $e$ could be measured.

\subsection{Geolocation via Multi-Image Constraint Solving}

\todo{This is the novel contribution of your pipeline. Explain:
\begin{itemize}
  \item For a single image with timestamp $t_k$ and predicted elevation
        $\hat{\theta}_k$, equation~\eqref{eq:sunmodel} yields a locus of
        $(\phi, \lambda)$ pairs (a curve on the Earth's surface).
  \item Two or more such curves (from different times) intersect at the
        true location.
  \item How you solve for the intersection (e.g.\ least-squares
        optimisation, grid search, or Levenberg--Marquardt on the residual
        $\sum_k (g(\phi,\lambda,t_k)-\hat{\theta}_k)^2$).
  \item Any ambiguities (e.g.\ hemisphere ambiguity) and how you handle them.
\end{itemize}
A small diagram showing the intersecting loci on a map would strengthen this
sub-section.}

We have seen we can find a circle of possible locations for where a measured elevation can occur. If we then take multiple easurements from 
multiple times throughout the year in the same area, we can obtain multiple of these sets of possible locations. The intersection
of these curves can be taken to find two unique points on the globe where the set of measurements must have come from.

Two unique points is as good as this method can do. These 2 points represent reflections around the equator.
Narrowing the potential points further is trivial in many cases. If one of the points is over the ocean, and the image we are trying to geolocate
is on dry land, we can discard it, for example.

In many cases we can contrain our potential location set by timezone. If the timestamp of the images includes a timezone such as NZST,
only the points of the circles within that timezone need to be considered. Many times this rules out one of the mirrored points as it
does not fall within the target timezone.

The geolocation estimate $(\hat{\phi}, \hat{\lambda})$ minimises:
\begin{equation}
    (\hat{\phi}, \hat{\lambda}) = \arg\min_{\phi,\lambda}
    \sum_{k=1}^{K} \bigl(g(\phi, \lambda, t_k) - \hat{\theta}_k\bigr)^2.
    \label{eq:optim}
\end{equation}
